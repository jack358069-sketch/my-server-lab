# 小服务器踩坑合集：那些"看起来能用"的地方

> 系列：个人服务器实验站复盘（三）
> 关键词：1Panel、Docker、OpenResty、Typecho、排错

复盘里最有价值的部分往往不是"我做了什么"，而是"哪里看起来对了、其实错了"。挑几个印象最深的写下来。

## 1. 127.0.0.1 探测 ≠ 线上正常

监控首页探测最初用 `http://127.0.0.1/`，返回 200，一切正常。实际上不带 Host 头的请求落到了 1Panel 的默认站点——**首页真挂了也不会报警**。

改成 `http.client` 直连 `127.0.0.1:80` 并显式带 `Host: <ServerName>`，才是真实访问路径。同类问题还有一个：LobeChat 探测返回 307 不是故障，是正常跳 `/chat`。**判断健康要看语义，不要只看"是不是 200"**。

## 2. 公网 IP 记错一位

一次连接全部超时，排查半天，最后发现 IP 记错了一位（115 和 116）。教训：**以能连上的地址为准**，别相信自己改过的笔记。现在所有配置里的地址都写进 `README.md` 和存档，只留一份来源。

## 3. 安全组 + 端口 + 面板入口，三处都要对

1Panel 只开 `IP:端口` 会提示"暂时无法访问"，必须用 `1pctl user-info` 拿完整地址（带安全入口路径）。Docker 用 host 网络模式时端口不经过映射，安全组要直接放行。**排"打不开"时，按 安全组 → 容器端口 → 面板入口 三段依次核对**，比乱试快得多。

## 4. 镜像拉取超时与 tag 不存在

默认加速源不稳；应用商店模板要求的 tag（比如 MariaDB `11.8.9`）有时不存在。解法都是从 `docker.1panel.live` 手动拉一个可用版本，`docker tag` 成模板期望的名字，安装时取消"拉取镜像"。**面板的模板是"意图"，镜像才是"现实"**。

## 5. 背景图"上传成功但看不见"

给站点加个性化背景，文件上传了、路径也对，就是不显示。原因是层叠顺序：背景层被内容层盖住，或者遮罩不透明度把图压没了。最后改成固定定位的底层 + 低遮罩，并把主题三档（跟随系统 / 浅色 / 深色）分别记忆。**"看不见"先查层级和透明度，再查路径**。

## 6. 主题功能缺失（搜索框）

Typecho 的 G 主题只渲染一个"搜索"链接，没有输入框。搜不了东西，体验就是断的。做法是用一个 `personalize.js` 补一个弹层输入框，回车后跳 `/index.php/search/<关键词>/`。**主题没做的功能，能用主题的"自定义底部 JS"补上，但要知道自己在改什么**。

## 7. 小内存机器的隐性成本

2G 物理内存，实际约 1.7GiB，四个容器一跑，内存就吃紧。加了 1GB swap，`vm.swappiness=10`——只在真需要时才用 swap，避免把热数据换出去。注意监控页显示的是物理内存占用，不含 swap，**看图时要分清"用了多少"和"还剩多少"**。

## 8. 数据库端口

MariaDB 的 3306 从第一天起就不对公网开放，Typecho 只通过容器网络访问它。这一类"能不能少开一个口"的选择，事后回看全是对的——**能不开的端口就别开**。

## 复盘

这些坑有个共同点：**都是"看起来正常"的地方**。所以我的排查顺序也慢慢固定下来：

1. 这个检查**有没有真的走到了目标**（Host、路径、端口、网络模式）；
2. 这个状态**在语义上是什么意思**（307 是不是正常、200 是不是默认站）；
3. 这个改动**有没有被别的层覆盖**（层级、透明度、缓存、模板）。

写下来是为了下次少走一遍弯路，也提醒自己：小机器上的问题通常不复杂，只是**藏得深**。
